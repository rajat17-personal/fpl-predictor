D-16 requires a declared budget before training begins, and leaves its exact size to implementation discretion. This plan declares it:

- **Seeds:** 3 fixed seeds (0, 1, 2), pinned in `config.py`.
- **Policies:** one per test season per seed, trained only on seasons strictly before that test season — 6 test seasons x 3 seeds = 18 policies.
- **Per-policy wall-clock cap:** 30 minutes, enforced inside the trainer, not by hope.
- **Total box:** 3 overnight runs (one per seed, roughly 3 hours each at the cap), which is the "handful of overnight runs" D-16 permits.
- **Hardware assumption:** GPU-accelerated, since `torch.cuda.is_available()` returned True on this machine on 2026-09-08 with the 2.12.0+cu130 build. If CUDA is unavailable at training time, halve the timestep budget rather than extending the wall-clock cap — the box is the constraint, not the timestep count.
- **Stop rule:** if the box is exhausted without beating plan 09-04's recorded `model+chips`, the experiment is recorded as rejected with its numbers (D-08). No open-ended tuning, no extra seeds, no "one more run".

Write this box into `IMPROVEMENTS.md` before training starts, so it cannot be quietly widened afterwards.
