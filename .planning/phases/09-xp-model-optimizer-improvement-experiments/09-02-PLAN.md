<assumption_delta_decision>
The assumption-delta detector fired on this phase (`pluralization`, on "additional enrichment data sources" in the ROADMAP goal). The identity model it points at is real: until now `player_code` from `data/id_map.py` has been the single player identity in this codebase, and this phase introduces three foreign identity namespaces (Understat, FotMob, FBref) at once.

- **Noun now primary:** player identity across data sources.
- **Decision: add-alongside.** `data/id_map.py` stays the sole authority for FPL identity, and `player_code` remains the canonical join key everywhere. `data/id_crosswalk.py` is an *alias table keyed by `player_code`*, not a competing identity model — it maps foreign names and ids onto the existing key rather than introducing a new abstract one.
- **Rationale:** `player_code` is already stable across seasons and already the join key in `data/build_table.py`, `features/engineer.py` and every optimiser pool. Promoting a generic identity abstraction would touch every one of those for no behavioural gain, in a phase whose entire value is measurement.
- **Accepted debt:** two identity modules now exist (`id_map.py` for FPL-internal identity, `id_crosswalk.py` for external aliases). A future phase that adds a fourth external source should consider merging them; until then the split is deliberate.
- **Suggested invariant test:** `tests/test_crosswalk.py` asserts a merge against the crosswalk leaves the row count unchanged, which is the generalized statement of "an alias table must never behave like an identity".
</assumption_delta_decision>
