<objective>
Turn the five Phase 6 success criteria into one repeatable command, and wire it into the local
preflight chain so every future push re-proves them.

Purpose: plans 06-01 through 06-04 prove their guarantees with pytest against a `TestClient`. Two of
those guarantees — the CORS trust boundary and the request-log redaction — are properties of a real
uvicorn process with real middleware ordering and real environment resolution, and Phase 5 already
learned the hard way (a bare `pytest` missing the CWD on `sys.path`, a missing shared library for
LightGBM) that the gap between an in-process test and a booted process is where the genuine bugs
live.

Output: `scripts/verify_hardening.sh`, which boots the API on the frozen fixture set and asserts the
runtime guarantees, plus a new preflight gate carrying it and the phase's static gates.
</objective>

  <action>
Create `scripts/verify_hardening.sh`, executable, with `set -euo pipefail` and a `cd` to the
repository root, following `scripts/smoke_test.sh`'s structure.

Interpreter and port seams, matching this repo's existing convention: `PY="${HARDENING_PYTHON:-python3}"`
and `HARDENING_PORT="${HARDENING_PORT:-8123}"`. Reuse `scripts/preflight.sh`'s `announce` / `fail` /
`record` helper shape so the output reads the same.

Boot one uvicorn process in the background with `FPL_FIXTURE_DIR=e2e/fixtures/v1/normal`,
`FPL_CORS_ORIGINS=https://fpl.example.com`, `FPL_API_KEYS=hardening-sentinel-key-do-not-log` and
`FPL_ALERT_LOG` pointed at a temporary file, redirecting the process's stdout and stderr to a
temporary capture file. Install a `trap` on EXIT that kills the process by PID and removes the
temporary files, so an assertion failure part-way through still tears the process down. Poll
`/api/health` for up to 30 seconds before asserting anything, and `fail` with the capture file's
contents if it never answers.

Then assert six gates, each announced by name, each calling `fail` with a `FAILED: [gate] reason`
line on breach:

1. **SEC-01 denied origin** — a request carrying an `Origin` header of `https://evil.example.net`
   returns a response whose headers contain no `access-control-allow-origin`.
2. **SEC-01 allowed origin** — a preflight OPTIONS carrying the configured origin and an
   `Access-Control-Request-Method` of POST returns `access-control-allow-origin` equal to that exact
   origin.
3. **OBS-02 liveness and readiness** — `/api/health` returns HTTP 200 with a body whose parsed keys
   are exactly `ok`, `gw`, `pool_age_s`; `/api/ready` returns 200 or 503 and its parsed body carries
   a `ready` key. Assert the two endpoints are distinct routes, not aliases, by asserting their body
   key sets differ.
4. **OBS-01 structured request log** — after the requests above, at least one line of the capture
   file parses as a JSON object whose `event` is the request event name and which carries
   `request_id`, `status` and `duration_ms`; and the health response carried an `X-Request-ID`
   header.
5. **SEC-03 no secret in the trail** — the sentinel key value was sent as an `X-API-Key` header on
   at least one of the requests above, and the string does not appear anywhere in the capture file.
6. **REL-04 actionable read failure** — `"$PY" -c` invoking `ops.jsonio.read_json` on a path that
   does not exist raises `PayloadError` whose message contains that path; a raw `FileNotFoundError`
   or `json.JSONDecodeError` escaping instead is a failure.

Use `curl -sS -D -` (or `-i`) to capture headers, and `"$PY" -c` for JSON parsing so the script
needs no jq. Header comparisons must be case-insensitive — HTTP header names are, and uvicorn
lower-cases them.

Finish with the same summary block shape `scripts/preflight.sh` prints, then a final
`HARDENING VERIFIED` line on success. Any gate that genuinely cannot run in the current environment
must be recorded as SKIPPED **by name** in the summary and counted separately — never omitted and
never counted as a pass.
