<objective>
Make the daily and weekly crons fail loudly and visibly, and move every secret behind a mode-600
`.env` that nothing tracked ever contains.

Purpose: today a failed FPL fetch inside `scripts/daily.sh` prints to a log nobody reads, a price
model crash is swallowed outright, and the only way to learn a run broke is to notice weeks later
that the price model never trained. That data cannot be backfilled. This plan gives every step an
explicit outcome, an immediate alert, and a non-zero exit — and gives the operator one file, with
one permission mode, that holds every credential.

Output: retry/backoff and atomic writes in `data/snapshot.py`, a never-raising `ops/notify.py`,
rewritten cron scripts with per-step accounting, workflows that delegate to those scripts instead
of duplicating them, and the `.env` pattern with its documentation and gates.
</objective>

Add `load_dotenv(path: Path | None = None) -> int` to `config.py` and call it once at module import,
after the paths block, so a single `import config` populates the environment for every CLI entry

`load_dotenv` reads the file at `path` (default `ROOT / ".env"`) if it exists, parses `KEY=VALUE`
lines, skips blank lines and lines whose first non-space character is `#`, strips one layer of
matching single or double quotes from the value, and sets each key in `os.environ` **only when that
key is not already set** — a container, a CI runner or an exported shell variable must always win
over the file, so a deployment can override without editing anything. It returns the count of keys
it set. It never raises: a malformed line is skipped with a one-line stderr warning naming the line
number, and an unreadable file is a warning, not a failure — the process must still start.

When the file exists, `load_dotenv` checks its permission bits with `stat.S_IMODE` and, if they are
anything other than `0o600`, prints a one-line stderr warning naming the file, the observed octal
mode, and `chmod 600 .env` as the fix. It does not refuse to load — refusing would take the API down
over a file-mode problem — but the warning must be unmissable.

Create `.env.example` at the repository root listing every environment variable this project reads,
each with a preceding comment line explaining what it is, whether it is optional, and where the
value comes from: `FPL_API_KEYS`, `ODDS_API_KEY`, `FPL_CORS_ORIGINS`, `FPL_ALERT_WEBHOOK`,
`FPL_ALERT_LOG`, and the two E2E fixture-mode seams `FPL_FIXTURE_DIR` and `FPL_FIXTURE_DATA_DIR`
with an explicit warning that the fixture seams must never be set in a production configuration.
Every key is written with an **empty** value — defaults belong in the comments, never on the
assignment line, so the file can be gated generically for the absence of values. The file's header
comment must instruct the reader to copy it to `.env` and run `chmod 600 .env`.

Add a "Secrets and configuration" section to `README.md` covering: the `.env` file and its mode-600
requirement; that `.env` is git-ignored while `.env.example` is tracked; that already-set
