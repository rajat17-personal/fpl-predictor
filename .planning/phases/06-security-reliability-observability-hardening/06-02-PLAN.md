<objective>
Close the file-handle leak inventory across the pipeline, model and product layers, and give every
JSON load an actionable failure message, using the `ops.jsonio` helpers the Wave 1 tracer proved.

Purpose: `CONCERNS.md` lists a concrete inventory of `open()` calls with no context manager, whose
observed symptom is `[Errno 24] Too many open files` on a long-lived uvicorn process, with
"restart the API periodically" as the current workaround. The same edit that closes those handles
also converts each uncaught `FileNotFoundError` / `JSONDecodeError` into a message that names what
to run — REL-01 and REL-04 are the same edit at most sites.

Output: 24 converted call sites across nine files, plus a repository-wide regression gate that
keeps the inventory at zero.
</objective>
