<objective>
Close the REL-05 TOCTOU race: make the (pool, pool_version) pair that `/api/solve` and `/api/plan`
key their cache on come from ONE critical section, and prove it with a test that drives the real
`_pool()`/`_refresh()` interleaving rather than a stub.

Purpose: 06-04 shipped the bounded LRU/TTL solve cache and the monotonic `pool_version` that
invalidates it, but its own SUMMARY records the decision that caused this gap — "Read
`_state['pool_version']` under a short separate `with _lock` block inside `solve()`/`plan()` rather
than changing `_pool()`'s return signature". `_pool()` calls `_refresh()`, then acquires the lock,
then releases it and returns the pool without the version it read the pool under; the handler then
acquires the lock a SECOND time to read `pool_version`. A refresh landing in that window makes the
handler compute its payload from the OLD pool and store it under the NEW version — a stale payload
indistinguishable from a fresh one for up to SOLVE_CACHE_TTL_S, with no error, no log line, and no
way for a caller to detect it. That is the exact failure class this phase exists to eliminate, and
`06-VERIFICATION.md` records it as a gap against roadmap Success Criterion #5 rather than an
accepted residual risk. Every existing test that touches this area replaces `_pool` with a
version-independent stub, so none of them can see it.

Output: `_pool()` and `_gw_pools_meta()` returning four-field snapshots whose version is read in the
same locked block as the pool; four handlers that hold no lock and touch no state dict; a
deterministic, stub-free regression test that fails against the pre-fix implementation by serving a
stale payload; a non-vacuity control proving the timing hook really opens the window; and an AST
gate that makes the two-acquisition shape impossible to re-introduce silently.
</objective>

**The hook: `_WindowLock`.**

`api/main.py` uses on `_lock`), plus public `armed`, `fired` and `on_window` attributes. `__enter__`
acquires and returns self. `__exit__` decides `fire = armed and not fired`, sets `fired` when firing,
**releases the lock, and only then calls `on_window()`** — so the callback runs at precisely the
instant the old code had its window: lock released, handler about to re-acquire. The `fired` latch is
what stops the callback recursing when `on_window` itself takes the lock. Document in the class
docstring that this reproduces the interleaving the old two-acquisition handler was vulnerable to,
deterministically and with no sleep.

**The shared setup: `_install_race_window(monkeypatch, m)` returning the `_WindowLock`.**
It monkeypatches three things on `api.main` and returns the lock:
- `_load_live` — a generation-tagged loader. Each call increments a counter `n`, builds a fresh
  `fake_boot()`, rewrites every element's `web_name` to `f"G{n}-{code}"`, and returns `(boot, [])`.
  Generation 0 is the pool a request starts with; generation 1 is what the injected refresh installs.
- `_intervals_artifact` — returns `None`, so `_with_bands` is a no-op and the response body does not
  depend on whether a developer machine happens to have an intervals artifact on disk.
- `_lock` — a fresh `_WindowLock` whose `on_window` calls `m._refresh(force=True)`.
It must NOT monkeypatch `_pool`, `_gw_pools_meta`, `_refresh`, `_cache_get` or `_cache_put`. Say so in
its docstring, and name the reason: those are the code paths under test.

Each test then monkeypatches only the *pool builder* it needs — a dependency of `_pool()`, never
`_pool()` itself — with a wrapper that arms the lock on its first call (`if not lock.fired:
lock.armed = True`) and returns `fake_pool(boot)` built from whichever bootstrap payload it was
handed. Arming inside the builder is what guarantees the callback fires on the exit of `_pool()`'s
own critical section rather than some earlier one.

**Gate: `test_solve_never_serves_a_pre_refresh_payload_under_a_post_refresh_key(monkeypatch)`.**
Install the race window, monkeypatch `m.build_pool` with the arming builder, delete `FPL_API_KEYS`,
and — after all monkeypatching, immediately before the first request — assert that
`m._pool.__name__ == "_pool"` and `m._pool.__module__ == "api.main"`. That assertion is the test's
own guarantee that it is driving the real accessor, and it is what makes this gate different from
every concurrency test that came before it.

Then `POST /api/solve` twice through `TestClient`, with the byte-identical body `{"horizon": 1}` both
times so both requests hash to the same key modulo the pool version. Assert the first response's
squad names are all generation 0 (the pool that existed when the request started), and then assert
**the second response's squad names are all generation 1**. Put the observed names in the assertion
message.

That second assertion is the whole gate. During the first request the injected refresh installs
generation 1, clears the pools and bumps the version; the pre-fix handler tagged its generation-0
payload with the post-refresh version, so the second request — which computes that same post-refresh
key — was answered from the cache with generation-0 data. This exact test, run against the current
pre-fix `api/main.py` before this plan was written, failed with
`STALE PAYLOAD SERVED AFTER A REFRESH: ['G0-1001', 'G0-1002', ...]`. Post-fix the first request's
payload is tagged with the pre-refresh version, the second request's key misses, and generation 1 is
computed and returned.

**Control: `test_the_window_hook_opens_a_real_gap_for_a_two_acquisition_reader(monkeypatch)`.**
The non-vacuity proof. Same setup and same arming builder, but no HTTP: call `m._pool(1)` directly to
get a snapshot, then reproduce the OLD read shape inline in the test — take `m._lock` in a separate
block and read the pool version from the state dictionary. Assert that this separately-read version is
exactly one greater than the snapshot's, and that the bootstrap payload now in the state dictionary is
a different object from the snapshot's. Together those two assertions prove the hook really did open
the window and land a refresh in it — so a green result from the gate above means the race was closed,
not that the window never opened. Its docstring should say plainly that this test deliberately
performs the two-acquisition read the production code no longer performs, and that if it ever stops
observing a difference the gate above has gone vacuous.

Constraints: no `time.sleep` and no thread in either test — both are single-threaded and fully
deterministic. No network call and no model-artifact load. No new dependency. Do not spell the
builtin file-opening call contiguously anywhere in this module, since `tests/test_reliability.py`'s

| Boundary | Description |
|----------|-------------|
| a cached solve/plan payload → the API caller | The caller has no way to tell a stale payload from a fresh one; the cache key's `pool_version` is the ONLY thing carrying that claim, so a mis-tagged key is a lie the caller cannot detect |
