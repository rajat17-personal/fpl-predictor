<objective>
Close UAT gap G-02-2: the H/A venue label sits beside the opponent code and reads awkward; the
user asked for it below the code.

This is a parity regression, not a design-change request. Vanilla already stacks the venue letter
below the code — web/assets/style.css:155 sets the small element to display block inside an
inline-block, text-centered chip at style.css:152 — and web/fixtures.html:74-75 has structurally
identical markup to the port. Only the CSS diverged: FdrCell.tsx:61 renders the chip as a
row-direction flex container, which blockifies the small element into a flex item on the main axis
so it can never begin a new line. Tailwind has no utility that expresses "make my child display
block", so the port restructured the chip and restructured it into a row.

Three coupled sub-deviations arrived with it and have to be fixed together, or the stacked chip
looks worse than the inline one: the 56px minimum width sits on the wrapper rather than on each
chip (the two branches of FdrCell already disagree about this), the gameweek cells use the generic
table padding instead of vanilla's fixture-specific tight padding that exists precisely to absorb a
two-line chip, and the chip uses the sans Label family where vanilla uses mono.

Purpose: restore vanilla's ticker cell, and leave behind the geometry assertion that would have
caught this — the existing seven FdrCell tests query text only and pass identically under either
layout.

Output: a column-stacked, minimum-width, monospace fixture chip; vanilla's tight gameweek cell
padding; and regression tests that pin the geometry.
</objective>
