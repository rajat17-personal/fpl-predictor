# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Scope Note

This phase (UI-02..UI-06, UIX-02) **extends** the Phase 1 app-shell contract
(`.planning/phases/01-test-base-layer-app-skeleton/01-UI-SPEC.md`) — it does not restart it.
Phase 1's tokens, spacing scale, route table, `PageShell` chrome, and `68rem` containment
geometry all carry forward unchanged unless a row below explicitly says otherwise. This document
adds: seven real page contracts (xP table, Fixtures, Prices, League, Scoreboard, Differentials,
Methodology — `/team` stays a Phase 3 placeholder), the upgraded GW meta-banner chip (UI-06), the
Light/Dark/System toggle (UIX-02), and the accessible status-flag tooltip pattern (D-09).

**Parity model governing every row below (from `02-CONTEXT.md`, locked, not re-litigated):**
behavioral parity, not visual cloning (D-01); the xP table keeps vanilla's top-50 free-preview
cap (D-02); all page copy ports verbatim (D-03); every intentional deviation is logged in
`.planning/phases/02-data-layer-non-pitch-pages/PARITY-DEVIATIONS.md` (D-04, file created during
planning/execution — this document seeds the known entries below); parity is verified by one
Vitest assertion per inventoried vanilla rule (D-05); the xP table is the flagship — deepest
coverage when trading off effort (D-06).

**Explicitly deferred to Phase 3 (do not build here):** `/team` real content, pitch renderer,
shirts/kits, p10/p90 interval bands on player *cards* (the interval **band cell** in tables is
Phase 2 scope — it already exists on the vanilla xP/Differentials tables), chip-timing UI,
lock/exclude/solve interactions.

### GW meta banner chip (UI-06, D-18..D-22)

Replaces Phase 1's empty meta-banner slot, in `PageShell`'s header `ml-auto` region. Pill
container: `--color-surface` background, `--color-line` border, rounded-full, Label-size
(14px) IBM Plex Mono text, `--color-ink-2`. One `meta.json` fetch (TanStack Query) shared by
`PageShell` across every route — not refetched per page.

| State | Trigger | Copy | Style |
|-------|---------|------|-------|
| Loading | Initial `meta.json` fetch in flight | `loading…` (verbatim from vanilla, D-03) | Muted pill, no icon |
| Populated — countdown | Fetch succeeded, deadline in the future | Line 1: `GW{gw} deadline: {abs} · {rel}`. Line 2 (new, D-20): `generated {freshness}` | Two stacked lines inside the pill; Line 1 `--color-ink-2`, Line 2 smaller/lighter (still Label size, same color — no new size token) |
| Populated — deadline passed | Fetch succeeded, deadline `<= now` | Line 1: `GW{gw} deadline passed` (D-21 — replaces the countdown segment entirely, not vanilla's `· passed` suffix). Line 2 unchanged (`generated {freshness}`) | Same pill, no color escalation (this is expected, not an error) |
| Fetch failed | `meta.json` 404/network error | `deadline TBC` (verbatim from vanilla's `fmtDeadline` null-guard, D-22) | Quiet fallback — **not** the rich `ErrorState`/`Retry` pattern (deliberate carve-out per D-22); no Line 2; every page's own data renders normally underneath |

**`{abs}` format** (unchanged from vanilla `fmtDeadline`): `Intl`/`toLocaleString` with
`{ weekday: "short", day: "numeric", month: "short", hour: "2-digit", minute: "2-digit" }`, e.g.
`Fri, 4 Sep, 17:30`.

**`{rel}` format** (upgraded per D-19 — graduated precision, ticks live):
| Remaining | Format | Example |
|-----------|--------|---------|
| ≥ 1 day | `in {d}d {h}h` | `in 3d 2h` |
| < 1 day, ≥ 1 hour | `in {h}h {m}m` | `in 4h 12m` |
| < 1 hour (optional, Claude's discretion — include only if it falls out naturally) | `in {m}m {s}s`, per-second tick | `in 8m 42s` |

Recompute cadence: every 60s via `setInterval` outside the final hour; every 1s inside the final
hour **only if** the per-second row above is implemented (falls back to `in {m}m` per-minute
otherwise — never omit the final-hour state, just choose its granularity).

**`{freshness}` format** (new, D-20 — from `meta.generated_utc`):
| Elapsed | Format | Example |
|---------|--------|---------|
| < 60s | `generated just now` | |
| < 60min | `generated {m}m ago` | `generated 42m ago` |
| < 24h | `generated {h}h ago` | `generated 2h ago` |
| ≥ 24h | `generated {d}d ago` | `generated 3d ago` |

### Dark mode toggle (UIX-02, D-14..D-17)

Segmented group of 3 icon buttons, same pill styling family as the GW chip (`--color-surface`
bg, `--color-line` border, rounded-full), positioned immediately after the GW chip in the
header's `ml-auto` region (wraps to its own row with the chip at narrow widths, same
`flex-wrap` behavior Phase 1 already applies to the header).

| Button | Icon (lucide-react) | `aria-label` | Value stored |
|--------|---------------------|--------------|---------------|
| Light | `Sun` | `Light theme` | `light` |
| Dark | `Moon` | `Dark theme` | `dark` |
| System | `Monitor` | `System theme` | `system` |

- Active button: `aria-pressed="true"`, `--color-accent-bg` background + `--color-accent-ink`
  icon (same active-state token pairing as the nav's active link). Inactive: `--color-ink-2`
  icon, `--color-surface-2` on hover. Each button is a 44px minimum touch target (spacing
  exception, carried from Phase 1's nav-link rule).
- Default (no stored preference): `system` (D-14).
- Persistence key: `localStorage["fpl-theme"]`, value `"light" | "dark" | "system"` (D-16).
- When resolved value is `system`, the resolved theme tracks
  `window.matchMedia("(prefers-color-scheme: dark)")` live — attach a `change` listener while
  mounted so an OS-level theme switch updates the site without a reload.
- Applied via a `dark` class on `<html>` — `document.documentElement.classList.toggle("dark", …)`
  — **not** a media-query-only strategy. This requires `frontend/src/index.css`'s dark token
  block to move from Phase 1's `@media (prefers-color-scheme: dark)` wrapper to a class-based
  Tailwind v4 dark variant (`@custom-variant dark (&:where(.dark, .dark *));` + a `.dark { … }`
  selector block wrapping the *same* variable values Phase 1 already declared). No token
  **values** change — only the selector strategy, so this is additive to Phase 1's token file,
  not a rewrite.
- Flash prevention (D-16): an inline `<script>` in `frontend/index.html`'s `<head>`, before
  `#root` and before any bundle loads, synchronously reads `localStorage["fpl-theme"]`, resolves
  it (falling back to `matchMedia` for `"system"`/unset), and sets the `dark` class on `<html>`
  immediately.
- LocalStorage write failure (private browsing, storage disabled): degrade to session-only
  in-memory state — the toggle still works for the current tab, it just doesn't persist. No
  user-facing error surface for this (see UI Considerations E9).

### Status-flag tooltip (D-09, shared by the xP table and Differentials table)

Replaces vanilla's desktop-only `title` attribute with a tap/click-friendly, keyboard-accessible
pattern — cheapest accessible option, no new dependency (Claude's discretion).

- Renders inline after the player name only when `status !== "a"` — identical trigger logic to
  vanilla's `statusFlag()`.
- Glyph/color logic unchanged from vanilla: status in `["i","s","u","n"]` → `✕` in
  `--color-bad`, `aria-label="unavailable"`; any other non-`"a"` status → `▲` in `--color-warn`,
  `aria-label="doubtful"`.
- Implementation: a `<button type="button">` (not a bare `<span title>`) wrapping the glyph,
  sized to a 44px touch target via padding (glyph itself stays visually small), with:
  - `aria-label` per the table above (verbatim from vanilla)
  - `aria-describedby` pointing to a tooltip `<span role="tooltip">` containing `r.news`
    (falling back to the label word, matching vanilla's `r.news || label`)
  - Tooltip visible on `:hover`, `:focus-visible`, **and** click-toggle (`aria-expanded`) for
    touch devices with no hover — click-outside or `Escape` closes it.
- Tooltip content max-width: 240px, wraps within that width, never clipped.

### `/` — xP table (flagship, D-06)

| Column | `data-key` | Type | Format |
|--------|-----------|------|--------|
| Pos | `position` | string | as-is (`GK`/`DEF`/`MID`/`FWD`) |
| Player | `name` | string | name + `StatusFlag` if `status !== "a"` |
| Team | `team_short` | string | as-is |
| £m | `price_m` | numeric | `.toFixed(1)` |
| Own % | `ownership` | numeric | `.toFixed(1)` or `–` if null |
| xP (10–90% band) | `xp` | numeric | band cell — see below |
| Captain xP | `xp_capt` | numeric | `.toFixed(2)` or `–` if null |

- **Data**: `xp_table.json`, sliced to the first 50 rows **without re-sorting** (source arrives
  pre-sorted by xP descending from the pipeline — port this assumption unchanged, D-02 cap).
- **Sort**: click a `data-key` header to sort by it; click the same header again reverses
  direction. Fresh key always starts descending (matches `makeSortable`'s `dir: -1` default).
  Numeric compare: `(y ?? -1e9) - (x ?? -1e9)` — null sorts to the bottom on descending, top on
  ascending. String compare: `localeCompare`, same null-to-`""` handling. Ports `makeSortable`
  1:1 as a reusable hook/utility (used by every sortable table this phase, see Fixtures note on
  which pages are **not** sortable).
- **Filters**: position chips (`ALL`/`GK`/`DEF`/`MID`/`FWD`, single-select, `aria-pressed`
  toggle group) AND case-insensitive substring search over `name`/`team`/`team_short`
  (trimmed). Both apply on top of the already-sliced top-50, matching vanilla exactly (searching
  never reaches back into rows 51+).
- **Band cell** (`bandCell`, verbatim tooltip copy per D-03): main value `xp.toFixed(2)`; track
  spans `p10`–`p90` as a percentage of `maxHi` (`Math.max(...top.map(r => r.p90 ?? r.xp))`); dot
  at `xp`; range label `{p10.toFixed(1)}–{p90.toFixed(1)}`. Tooltip: `xP {xp.toFixed(2)} —
  actual score lands between {lo.toFixed(1)} and {hi.toFixed(1)} in 8 gameweeks out of 10` where
  `lo = p10 ?? xp`, `hi = p90 ?? xp`.
- **Captain picks sub-table** (`h2` "Captain picks"): top 5 of `captains.json`, columns
  Player/Team/£m/Own%/Captain xP, static (no sort, no filter).
- **Copy** (verbatim, D-03): see Copywriting Contract.

## Typography

Carried unchanged from Phase 1 — `Label`(14px/400/1.4), `Body`(16px/400/1.5),
`Heading`(20px/700/1.2), `Display`(28px/700/1.15). Still exactly two weights, still exactly four
sizes. This phase **activates** the reserved Numeric/Mono modifier and maps every vanilla
font-size variant onto these four roles:

| Vanilla element | Vanilla size | Mapped role | Family | Notes |
|---|---|---|---|---|
| `h1` | 1.6rem/800 | `Display` (28px/700) | Archivo | weight capped at 700 |
| `h2` | 1.15rem/700 | `Heading` (20px/700) | Archivo | unchanged mapping |
| `.sub`, `.note`, prose paragraphs | 0.9–1rem | `Body` (16px/400) | IBM Plex Sans | all prose blocks |
| Table `td`, nav links, chips, legend, tile `.d` caption | 0.78–0.9rem | `Label` (14px/400) | IBM Plex Sans | compact UI chrome |
| Table `td.n`, `.n`, band `.val`/`.range`, deadline chip, GW banner | 0.72–0.84rem mono | `Label` (14px/400) | **IBM Plex Mono**, `tabular-nums` | "Numeric" modifier — same size as Label, different family |
| Table `th`, tile `.k` label, leaders board `h3` | 0.66–0.68rem uppercase | `Label` (14px/700) | Archivo, uppercase, `letter-spacing: 0.08em`–`0.1em` | "eyebrow" style — Label size, Heading family+weight |
| Tile `.v` value | 1.5rem/500 mono | `Display` (28px/700) | IBM Plex Mono, `tabular-nums` | weight rounds up to 700 (no 500 in the 2-weight contract) — ledger entry 8 |

**Numeric modifier rule**: any Label or Body text rendering tabular/numeric data (prices,
ownership %, xP, MAE, correlation, GW numbers, countdown, dates in the mono chip) uses
`font-family: IBM Plex Mono` + `font-variant-numeric: tabular-nums` at the *same* size/weight/
line-height as its assigned role — never a new size.
