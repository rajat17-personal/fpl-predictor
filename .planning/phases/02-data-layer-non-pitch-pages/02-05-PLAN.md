<objective>
Port the league page (`/league`) and the accuracy scoreboard (`/scoreboard`) to behavioural parity
with the vanilla site.

Purpose: these two close out half of UI-05. The scoreboard carries the phase's single genuine
behavioural upgrade over vanilla — vanilla swallows every fetch failure into "no data yet", while
D-08 requires distinguishing a genuinely-absent pre-season file from a server failure. It is also
the page the product's honesty claim rests on, so the pre-season copy and the history-row set have
to be exactly what the export says and nothing else.

Output: fully-ported `routes/League.tsx` and `routes/Scoreboard.tsx`, plus three parity fixtures
including a synthesised populated scoreboard the live pipeline cannot produce yet.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pipeline → browser | `standings.json`, `leaders.json` and `scoreboard.json` string fields are rendered as page text |
| network status → UI state | An HTTP status code selects between a business zero-state and an error state |

|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-10 | Spoofing | A server or proxy failure being presented to the user as "no gameweeks scored yet" | medium | mitigate | `fetchScoreboard` branches explicitly on the missing-file status and throws for every other non-ok status, so only a genuinely absent file reaches the zero-state; a dedicated 500 test asserts the Retry control appears and the backtest copy does not |
| T-02-11 | Information Disclosure | `ErrorState` on a failed scoreboard or league fetch | low | mitigate | The Phase 1 `ErrorState` takes only a resource label; the thrown Error's message, which embeds the request path and status, goes to `console.error` and never into the DOM |
</threat_model>
