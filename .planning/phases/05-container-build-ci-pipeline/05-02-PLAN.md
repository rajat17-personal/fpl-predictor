<objective>
Author the multi-stage container image and the smoke test that proves it can do real work. The image
is code plus locked dependencies plus both static frontends — no model artifact (D-05). The smoke test
boots the container against the frozen v1 fixture set, asserts `/api/health`, then POSTs a real
`/api/solve` so an actual integer program runs through the CBC binary inside the container.

Purpose: CI-03. "The CBC solver is available" is a claim that only a completed solve can settle;
`import pulp` proves nothing. And "the container boots without a model" is exactly what makes D-05's
model-at-deploy-time posture workable.

Output: `Dockerfile`, `.dockerignore`, `scripts/smoke_test.sh`.
</objective>

    Create `Dockerfile` at the repository root, opening with the short "what this does and why" comment

    Builder stage: `FROM python:3.14-slim AS builder`, `WORKDIR /app`, copy only `requirements.txt`,
    then install it with `pip install --require-hashes --prefix=/install -r requirements.txt` — the
    hash-enforced install form D-04 mandates for every consumer of the lock. Copying
    the lock alone before the install keeps the dependency layer cacheable across source-only changes.
    If plan 05-01's SUMMARY recorded that a package needed a source compile, add `build-essential` to
    this stage (and only this stage) before the install — that is D-03's pre-authorized fallback; if the
    SUMMARY recorded a clean wheel install, do not add a compiler.

    Runtime stage: `FROM python:3.14-slim AS runtime`. Install `libstdc++6` with
    `apt-get update && apt-get install -y --no-install-recommends libstdc++6 && rm -rf /var/lib/apt/lists/*`
    in one layer. This is not optional and not cosmetic: the CBC executable that ships inside the PuLP
    wheel at `pulp/solverdir/cbc/linux/i64/cbc` is a C++ binary, and the official slim image purges
    every apt library CPython itself does not link — CPython links no C++ standard library, so it is
    absent by default and every solve would fail at subprocess launch. Add a one-line comment above the
    apt line saying exactly that, so nobody "optimizes" it away later.

    Copy the built dependency tree with `COPY --from=builder /install /usr/local`, set `WORKDIR /app`,
    then `COPY . .` — the build-context exclusion list below, not a hand-maintained COPY list, is what
    decides what lands in the image. Create a non-root account (`useradd --create-home --uid 10001
    appuser`), `chown` `/app` to it, and `USER appuser` before the entrypoint. `EXPOSE 8000`. Add a
    `HEALTHCHECK` that calls `/api/health` through `python -c` with `urllib.request` (no extra package,
    and it works whether or not curl is in the image). Entrypoint is
    `CMD ["uvicorn", "api.main:app", "--host", "0.0.0.0", "--port", "8000"]`.

    Nothing anywhere in the file may copy, download, or reference a model artifact — the image is code
    plus locked dependencies plus static assets, and the model arrives at deploy time next milestone
    (D-05). `api/main.py`'s `/api/health` reads `_state` without calling `_refresh()`, and `_refresh()`
    only reaches `joblib.load` when the fixture root is unset, which is why a model-less image still
    boots and still answers health and fixture-mode solves.

    Create `.dockerignore` at the repository root, mirroring `.gitignore`'s categories with the same
    section-comment style, and adding what `.gitignore` deliberately keeps tracked but the image has no
    use for. It must exclude at minimum, one per line, each as an exact line so the verification gate can
    confirm it: `.git`, `.github`, `.planning`, `.claude`, `.gsd`, `tests`, `e2e`, `scripts`, `docs`,
    `downloaded_files`, `models/artifacts`, `data/raw`, `data/processed`, `data/snapshots`,
    `data/cron.log`, `node_modules`, `frontend/node_modules`, `__pycache__`, `.pytest_cache`, `*.deb`,
    `.env`, `.env.*`, `*.tsbuildinfo`, `*.md`.

    Two deliberate divergences from `.gitignore`, each with an inline comment explaining why:
    - `.gitignore` re-includes the daily price-snapshot history because it cannot be backfilled;
      `.dockerignore` must NOT re-include it — snapshot history has no business inside a stateless image.
    - `.gitignore` excludes the built React bundle from version control; `.dockerignore` must leave that
      directory in the build context, because D-06 requires it inside the image and CI builds it before
      `docker build` runs. Achieve this by excluding `frontend/**` and then re-including the two lines
      `!frontend/dist` and `!frontend/dist/**`. Note that `.dockerignore` uses Go path-match semantics,
      not gitignore semantics: a leading-`*` pattern like `*.md` matches root-level files only, which is
      what keeps `frontend/src/content/methodology.md` and any future `web/` markdown reachable.

    Create `scripts/smoke_test.sh`, executable, following `scripts/verify_frontend_build.sh`'s
    conventions exactly: `#!/usr/bin/env bash`, a purpose comment block stating that this proves a real
    integer program runs through the bundled CBC binary inside the container rather than merely that the
    solver package imports, a `Usage:` line, `set -euo pipefail`, and `cd "$(dirname "$0")/.."` so it
    runs from any working directory.

    Take the image tag as `$1`. Read two environment seams with defaults, mirroring the `E2E_PYTHON`
    pattern this repo already uses for exactly this reason: `SMOKE_DOCKER` (default `docker`) names the
    container CLI, and `SMOKE_PORT` (default `8200`) names the host port. Do not use port 8000 — a
    developer's own `uvicorn api.main:app --port 8000` serving live data would be silently adopted, the
    same trap `playwright.config.ts` documents for its own port choice.

    Two fail-fast guards, in this order, each with a distinct named message so the caller knows which
    one fired:
    1. No image tag argument → print a `FAILED:` line naming the missing argument and the usage form,
       then exit 1.
    2. `command -v` on the container CLI finds nothing → print a `FAILED:` line that names the missing
       runtime, the value of the seam that selected it, and how to override it, then exit 1.

    Then the run itself. Register an `EXIT` trap that force-removes the container so a failed assertion
    never leaks a running container. Start the image detached under a name derived from `$$`, publishing
    the chosen host port to container port 8000, with `FPL_FIXTURE_DIR` set to `/fixtures/v1/normal` and
    the repository's `e2e/fixtures` directory bind-mounted read-only at `/fixtures`. The fixture set is
    bind-mounted, never copied into the image — it is test data and `.dockerignore` already excludes it.

    Poll `/api/health` with `curl -fsS` on a bounded loop (about 30 attempts, one second apart). On
    timeout, print a `FAILED:` line naming the endpoint and elapsed budget, dump the container logs so
    the failure is diagnosable from CI output alone, and exit 1 — never retry forever and never fall
    through silently.

    Then POST `{}` to `/api/solve` with a JSON content type. An empty body is valid because every field
    on the request model carries a default, so this triggers a genuine from-scratch squad solve rather
    than a cached or trivial path. Assert the response by counting `player_code` occurrences: a legal
    FPL squad is exactly 15, and that count is only reachable if the integer program actually solved. On
    mismatch, print a `FAILED:` line naming the expected and observed counts, echo the response body,
    and exit 1. On success print the bracketed status lines and a final `SMOKE TEST PASSED`.

    Make the script executable (`chmod +x`) so CI can invoke it as `bash scripts/smoke_test.sh` or
    directly.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repository working tree → image build context | Everything not excluded by `.dockerignore` becomes a readable layer in a registry-published artifact |
| container process → host | The published port and the bind-mounted fixture directory are the only surfaces the container exposes or consumes |
| PyPI wheel contents → container execution | The CBC executable shipped inside the PuLP wheel is run as a subprocess by application code |
