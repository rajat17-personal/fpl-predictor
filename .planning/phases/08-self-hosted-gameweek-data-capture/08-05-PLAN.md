Add one step and one test.

Place the capture step immediately after the snapshot gap-report step and before the price-model
training step. The ordering is load-bearing in one direction: the snapshot step earlier in the same
run writes the day's snapshot, and on the morning after a gameweek's deadline that snapshot is what
the capture reads to resolve that gameweek's expected-points figure. Running the capture first would
cost the newly-settled gameweek its figure on the only day it is available to resolve.

Write the line in the same form as its five siblings: the wrapper, the step's name matching the module
path, the interpreter variable, and the module invocation. No flags — a plain run is what the daily
cadence wants, capturing whatever finished since yesterday and costing two requests when nothing did.
Keep the explicit if-block style this script already uses throughout; the short-circuit idiom was
deliberately removed from this file once before because it captured the wrong exit code.

Update the header comment's numbered step list to include the new step in its real position, so the
comment continues to describe the script rather than a previous version of it.

Then add the regression test to `tests/test_cron.py`, modelled directly on the existing gap-report
ordering test: read the script's text, locate the five existing step names and the new one, and assert
the new step appears after the snapshot gap report and before the price-model training step. Assert
also that the existing five appear in their current relative order, so a future edit that reshuffles
the script fails here rather than silently changing the pipeline's semantics.

Finally, run the wired step by itself, exactly as the cron will invoke it, and confirm it exits zero
and reports the freshness check as satisfied. That is the end-to-end proof that the wiring works — not
a full daily run, which would exercise four unrelated steps and take far longer.
