## The xP resolution rule, and why the research's phrasing would have been wrong

`08-RESEARCH.md` proposes "nearest snapshot with date on or before the gameweek's deadline, column
`ep_this`". The column half of that is wrong for exactly the gameweek it matters for, and the
following facts were measured on this machine on 2026-09-11:

| Fact | Value |
|---|---|
| Snapshot archive | four files: 2026-08-31, 2026-09-07, 2026-09-11, 2026-09-12 |
| 2026-08-31 snapshot's own recorded next gameweek | 3 |
| Gameweek deadlines | GW1 2026-08-21T17:30Z, GW2 2026-08-28T17:30Z, GW3 2026-09-04T17:30Z, GW4 2026-09-12T12:30Z |

The FPL payload's current-gameweek projection describes the event currently in progress and the
next-gameweek projection describes the one after it. The latest snapshot dated on or before GW3's
deadline is 2026-08-31, and that snapshot's own recorded next gameweek is 3 — so at capture time
GW3 was the upcoming event and its projection lives in the **next**-gameweek column. The
current-gameweek column in that same file projects GW2. Reading it, as the research's phrasing
says, would silently label every GW3 row with GW2's expectation.

The rule this plan implements, stated in terms of the snapshot's own recorded next gameweek `S`:

| Condition on the chosen snapshot | Column to read | Outcome for the current season |
|---|---|---|
| `S` equals the target gameweek | next-gameweek projection | GW3 resolves from the 2026-08-31 snapshot |
| `S` equals the target gameweek plus one | current-gameweek projection | the deadline-day-after-deadline case, reachable once the daily cron is wired |
| anything else, or no snapshot dated on or before the deadline | missing | GW1 and GW2 resolve to missing — permanently, and correctly |

vaastav's own published 2026-27 gameweek-1 file does carry real `xP` values. Sourcing them from
there is deliberately **not** done: it would reinstate the dependency this phase exists to remove,
it cannot be done for gameweek 2 (vaastav has no file for it), and it would leave one gameweek's
`xP` provenance different from every other. The gap is recorded, not filled. Plan 08-03's evidence
document states the null rate as a measured fact.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public FPL API → local disk | unauthenticated third-party JSON persisted as training-data CSVs, with field names the pipeline trusts |
| daily snapshot archive → captured CSV | an irreplaceable local archive is read to fill a model feature; a wrong read mislabels every row of a gameweek |
| capture process → cron wrapper | the module's exit code and its own alerting layer together decide whether a stalled capture is noticed |
