<objective>
Close the snapshot capture gap D-08 names: only 2 of the 10 days since 2026-08-31 were
captured (2026-08-31 and 2026-09-07) because WSL cron does not fire while the machine is off.
Add an anacron-style catch-up that captures today's snapshot on boot / first invocation of the
day when it is missing.

Purpose: this is the single most time-critical item in the whole project and it is independent
of every experiment in this phase. Price-model history and availability history cannot be
backfilled — `data/snapshots/` is the one directory `.gitignore` deliberately re-includes for
exactly this reason. Every day the machine is off is a row permanently lost from the price
model's training set and from the availability signal Tier 1 is built on.

Output: `scripts/snapshot_catchup.sh` (idempotent, safe to invoke arbitrarily often), a
`daily.sh` step that reports how many days are missing rather than silently skipping, and cron
failure-path tests in `tests/test_cron.py`.

`data/snapshot.py::take_snapshot` is already idempotent per UTC day (its `out.exists() and not
force` guard), so this is a scheduling fix and needs no new capture logic. This plan does not
modify `data/snapshot.py`.
</objective>

Create `scripts/snapshot_catchup.sh` with the same header as `scripts/daily.sh`
(`#!/usr/bin/env bash`, `set -euo pipefail`, `cd "$(dirname "$0")/.."`, the same
`PY="${PYTHON:-...}"` default). Its contract: safe to invoke arbitrarily often — on `@reboot`,
on shell login, and from `daily.sh` — because `data/snapshot.py` is already idempotent per UTC
day. Log every line with a `[catchup]` tag, matching this project's module-tagged print
convention.

Behaviour:
1. Compute `TODAY="$(date -u +%F)"` and check `data/snapshots/${TODAY}.parquet`.
2. If it exists, print `[catchup] ${TODAY}.parquet already present — nothing to do` and exit 0.
3. If it does not exist, invoke `"$PY" -m data.snapshot`. Capture the real exit code using the
   non-negated else-branch form (`if "$@"; then ...; else rc=$?; ...; fi`) — NOT
   `if ! CMD; then rc=$?`, which always captures 0 under bash if-negation semantics
   (the bug plan 06-03 already found and documented in `scripts/daily.sh`). Use no `||`
   anywhere in the file, matching the repo-wide convention 06-03 established.
4. On failure, alert through `"$PY" -m ops.notify --job catchup --step data.snapshot
   --message "exit code $rc"`, guarding that call in its own if-block so a failing alerter
   cannot mask the original failure, then exit with `$rc`.
5. Always print a gap report: count `data/snapshots/*.parquet` files and the number of calendar
   days between the earliest filename date and today, then print
   `[catchup] archive: N files spanning M days (K days missing)`. This is the number D-08's
   context is about, and it must be visible on every invocation.

Flags:
- `--report-only` — perform step 5 only, never capture. This is the form `daily.sh` calls, so
  the daily run's own `data.snapshot` step stays the single capture path there.
- `--print-cron` — print exactly the two crontab lines the developer needs, to stdout, nothing
  else: the existing `30 2 * * * /home/sraja/fpl/scripts/daily.sh >> /home/sraja/fpl/data/cron.log 2>&1`
  line as documented in `scripts/daily.sh`'s own header, and the new
  `@reboot /home/sraja/fpl/scripts/snapshot_catchup.sh >> /home/sraja/fpl/data/cron.log 2>&1`
  line. This exists so the human `user_setup` step is copy-paste, not transcription.

Document the whole contract in a header comment block, including the sentence that WSL cron
does not fire while the machine is off (the D-08 motivation) and that this script is the
compensating mechanism.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| crontab / boot sequence -> `scripts/snapshot_catchup.sh` | an unattended, unprivileged automatic invocation crosses here |
