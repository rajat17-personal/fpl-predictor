<objective>
Close UAT gap G-03-1: formation rows with an even number of cards (the 2-card FWD row, the
4-card DEF and MID rows, and the always-4-card bench) sit half a column-pitch left of the
pitch midline — ~61px at desktop, ~32px at 375px — while 1/3/5-card rows are exactly
centered.

Root cause (confirmed empirically in `.planning/debug/pitch-row-centering-drift.md`): the row
places all its cards on a single **integer** CSS grid start column inside a fixed 5-track
grid. True centering needs start `s = (C - n)/2 + 1`, which is an integer only when the card
count `n` and the track count `C` share parity. With `C` pinned at 5 (odd), every even `n`
needs a half-integer start that CSS grid cannot express; the floor discards the 0.5 and
shifts the whole row left. This is one defect in one shared row component — row cardinality
is the data-dependent trigger, not a second cause.

Purpose: restore the FPL-pitch read that UAT test 1 rejected, and close the coverage hole
that let a pure, trivially-unit-testable arithmetic function ship wrong — `Pitch.test.tsx`
today makes zero positional assertions.

Output: a continuously-centered row layout (no integer quantization, exact for every row
size), a symmetry regression test spanning row sizes 1-6 including the odd controls that
guard against an over-correction, and a corrected UI-SPEC so the defective mechanism is not
re-derived by the next implementer.
</objective>
