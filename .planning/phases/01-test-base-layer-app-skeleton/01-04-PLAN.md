<objective>
Prove the runtime seam the whole React rebuild depends on: a Vite dev server serving a React app
that reaches this repo's own FastAPI process for both `/api/*` and `/data/*.json`, with nothing from
the weekly pipeline baked into the build.

There is no frontend project in this repo yet — `web/` is framework-free multi-page HTML and there is
no `package.json` anywhere. The seam has one non-obvious detail that decides whether any of the
following six phases work: `api/main.py` mounts `StaticFiles(directory=config.ROOT / "web")` at `/`,
so `web/data/meta.json` is served at `GET /data/meta.json`, **not** `/web/data/meta.json`. A proxy
rule for the wrong prefix 404s every fetch in dev while looking perfectly reasonable in the config
file. This plan pins that down with a runnable check rather than a comment.

Purpose: land the smallest React app that genuinely reaches the backend, plus the design-token
architecture, shell chrome, and component-test harness that plan 01-05 and Phase 2 build on.
Output: `frontend/`, a proven dev proxy, a Tailwind v4 `@theme` token set, a `PageShell`, and a
working Vitest environment.

**Explicitly out of scope:** `CORSMiddleware(allow_origins=["*"])` in `api/main.py` stays untouched.
The Vite proxy makes every browser request same-origin (the browser talks only to `:5173`; Vite
forwards server-side to `:8000`), so CORS headers are never consulted in this flow. Restricting them
is Phase 6 `SEC-01`.

**Decision recorded** (`01-RESEARCH.md` Open Question 1): `frontend/` gets its own standalone
`package.json` and `node_modules`, not a root workspace. It is the simpler shape, and a root-level
npm workspace can be introduced in Phase 5 without changing anything inside `frontend/`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public npm registry → `frontend/node_modules` | `npm install` runs registry-controlled lifecycle scripts and then bundles registry-controlled code into a browser artifact |
| browser (`:5173`) → Vite dev server → uvicorn (`:8000`) | The dev proxy is a new network hop that did not exist in the vanilla site's single-origin model |
| pipeline export (`web/data/*.json`) → frontend build output | Copying instead of fetching turns live data into a stale artifact with no expiry |

| T-04-SC | Tampering | `npm install` of 12 registry-flagged `[SUS]` packages | high | mitigate | Covered by the `gate="blocking-human"` package-legitimacy checkpoint in plan 01-01; installs are restricted to that approved list, use `--save-exact`, and the resulting `package-lock.json` is committed so Phase 5's CI resolves the same tree |
| T-04-01 | Tampering | `npm create vite` installing whatever `typescript` is `latest` (7.0.2 today) | medium | mitigate | `typescript@6.0.3` pinned with `--save-exact` immediately after scaffolding and before any lint tooling is added; an automated gate reads the pin back out of `package.json`. 7.x sits outside `typescript-eslint`'s declared peer range and degrades the lint pipeline silently rather than erroring |
| T-04-02 | Information Disclosure | pipeline JSON copied into `frontend/dist` or `frontend/public` | medium | mitigate | `scripts/verify_frontend_build.sh` compares every built filename against `web/data`'s JSON filenames and fails the build on a match; also fails if `frontend/public/data` exists |
