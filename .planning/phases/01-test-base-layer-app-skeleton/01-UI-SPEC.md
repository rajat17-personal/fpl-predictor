# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Scope Note

This phase (UI-01 only — APIT-01/02/03 have no UI surface) builds the **app shell**, not page
content: layout frame, navigation, route structure for all 8 pages, the design token
architecture (dark-mode-ready per UIX-02 landing in Phase 2), and loading/error/placeholder
conventions for runtime `web/data/*.json` and `/api/*` fetches through the Vite dev proxy.

**Explicitly deferred to later phases (do not build here):**
- Per-page content, tables, sort/filter UI (Phase 2, UI-02..UI-06)
- FDR green→red ticker colors and cells (Phase 2, UI-03) — token slots reserved below, unused this phase
- Dark mode *toggle* UI/persistence (Phase 2, UIX-02) — token architecture must support it now; the switch itself does not ship this phase
- Pitch renderer, shirts/kits, p10/p90 interval bands, chip-timing UI (Phase 3)

**Design system decision made without a CONTEXT.md/user session (no `/gsd-discuss-phase` has run
for this phase):** shadcn was NOT initialized — see rationale under Design System below. Flagged
for the orchestrator/user to override if this call is wrong.

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — first-party components only (`frontend/src/components/`) |
| Icon library | lucide-react (MIT, tree-shakeable, no framework lock-in; standard pairing for Tailwind/React in 2026) |
| Font | Archivo (headings, 700) + IBM Plex Sans (body/UI, 400) + IBM Plex Mono (numeric/tabular data, 400) — loaded via Google Fonts `<link>`, same three families the vanilla site already uses |

**Why `Tool: none` (shadcn declined):** `components.json` does not exist and the stack is
Vite+React, which normally triggers the shadcn init gate. This is a **parity rebuild**
(explicit requirement) of a vanilla site with an already-distinctive, fully-worked hand-built
design system (`web/assets/style.css`) — specific fonts, a green accent, pill-shaped chips, a
validated FDR diverging color ramp used throughout later-phase research (`FEATURES.md`,
`STACK.md`). `STACK.md`'s own recommendation is Tailwind CSS v4 with no shadcn mention.
Introducing shadcn's Radix-based default styling now would fight the parity goal and require
re-theming every primitive to match the vanilla look, which is strictly more work than porting
the existing CSS custom properties into a Tailwind v4 `@theme` block. **If this call is wrong,
override by running shadcn init and re-deriving this file's tokens from the chosen preset.**

## App Shell Contract

> Structural/layout decisions the template's fixed sections don't have a slot for, but that
> this phase must lock per the objective (layout frame, nav, route structure, loading/error).

### Layout frame

| Element | Value | Source |
|---------|-------|--------|
| Content max-width | `68rem` (1088px), centered | Carried from vanilla `.wrap { max-width: 68rem }` — parity |
| Page horizontal padding | `16px` (mobile and up, this phase) | Carried from vanilla; per-page responsive scale-up is Phase 2 concern |
| Header | Non-sticky, static flex row: brand + nav + (meta banner slot, empty this phase) | Carried from vanilla `header.site` — do not make it sticky unless a later phase's UX research calls for it |
| Footer | Persistent, every page: general non-affiliation disclaimer text (see Copywriting) | Carried from vanilla `footer.site`. **Distinct from PITCH-01's Phase 3 shirt/kit-specific disclaimer** — this is the general "not affiliated with the Premier League" line already on every vanilla page today |
| Route content area | Below header, above footer, inside the `68rem` wrapper | — |

### Routes (8, declarative React Router 7, SPA mode — no framework/Remix mode)

| Path | Page | Phase 1 content |
|------|------|------------------|
| `/` | xP table | Placeholder |
| `/team` | Team (pitch + solver) | Placeholder |
| `/fixtures` | Fixtures | Placeholder |
| `/prices` | Prices | Placeholder |
| `/league` | League | Placeholder |
| `/scoreboard` | Scoreboard | Placeholder |
| `/differentials` | Differentials | Placeholder |
| `/methodology` | Methodology | Placeholder |
| `*` (catch-all) | Not Found | See Copywriting — 404 state |

Every route renders inside the same `PageShell` (header/nav/footer chrome) with its own
route-level error boundary (React Router `errorElement`), so one page's data-fetch crash never
takes down the nav shell or any other route.

### Loading / error components (shell-level, reused by every page's data fetch)

| Component | Behavior |
|-----------|----------|
| `<Spinner/>` + "Loading…" | Centered in the content area, accent-colored ring, shown while a TanStack Query fetch to `web/data/*.json` or `/api/*` is in flight. Reserve the content area's expected min-height so nothing jumps on resolve. |
| `<ErrorState/>` | Centered block: heading + body copy (see Copywriting) + a `Retry` button that calls the query's `refetch()`. Used for any failed `/data/*` or `/api/*` fetch. |
| `<PlaceholderPage/>` | Page title (Display token) + one line of body copy (see Copywriting). Used by all 8 routes this phase since no real content exists yet. |
| `<NotFoundPage/>` | Heading + body + link back to `/` (xP table). Rendered by the catch-all route. |

### Dark-mode-ready token architecture (built now, toggle ships Phase 2 UIX-02)

Every color below is a CSS custom property (ported into a Tailwind v4 `@theme` block) with a
light value on `:root` and a dark value gated behind a class/media strategy the executor picks
(`prefers-color-scheme` today, swappable for a `data-theme` attribute when the Phase 2 toggle
needs explicit user override rather than only OS preference). No component may hardcode a hex
value — every color reference goes through the token name.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing, nav link internal padding |
| md | 16px | Default element spacing, page horizontal padding |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing (footer top margin) |

Exceptions:
- Minimum interactive touch target `44px` (nav links, icon buttons) on mobile widths — WCAG 2.5.5, not itself a spacing token but a floor applied via padding on the `sm`/`md` tokens.
- Focus ring offset `2px` — an outline property, not a layout spacing token.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | Regular (400, IBM Plex Sans) | 1.4 |
| Body | 16px | Regular (400, IBM Plex Sans) | 1.5 |
| Heading | 20px | Bold (700, Archivo) | 1.2 |
| Display | 28px | Bold (700, Archivo) | 1.15 |

Exactly two weights in the contract: **Regular (400)** and **Bold (700)**. Weight and font
family are orthogonal — Regular renders in IBM Plex Sans (UI/body text) or IBM Plex Mono
(reserved for numeric/tabular data in later phases, not used by this phase's shell); Bold
renders in Archivo (headings, brand wordmark, nav active-state emphasis).

Usage in this phase: Label → nav links, footer disclaimer, loading/placeholder captions.
Body → error/placeholder body copy. Heading → brand wordmark, `<NotFoundPage/>` heading.
Display → `<PlaceholderPage/>` page title, `<ErrorState/>` heading.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Retry` — on `<ErrorState/>`, re-triggers the failed query's `refetch()`. No other primary CTA exists at app-shell scope; per-page CTAs (sort, filter, solve) are Phase 2/3 scope. |
| Empty state heading | "Nothing here yet" |
| Empty state body | "This data source returned no results. Try again shortly — the weekly export may still be running." |

## UI Considerations

Applicable state considerations resolved: 9 covered, 3 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| loading | Nav | ✅ covered | Nav is a static route-link list, not data-driven — no loading state applies this phase (the live deadline countdown in the meta-banner slot is Phase 2, UI-06) |
| error | Nav | ✅ covered | An unmatched path renders the catch-all `<NotFoundPage/>` (see Routes + Copywriting `404` rows) rather than a broken nav state |
| overflow | Nav | ✅ covered | 8 nav links wrap to a second row via flexbox at narrow viewports (`flex-wrap: wrap`), matching the vanilla site's existing behavior — no hamburger menu this phase |
| long-text | Nav | ✅ covered | Nav labels are 8 fixed, short, developer-authored strings — no variable-length or user-generated content risk |
| empty | Route data fetch (`web/data/*.json` / `/api/*` via TanStack Query, per page) | ✅ covered | Generic empty-state copy (see Copywriting `Empty state` rows) renders when a fetch resolves with zero rows/items |
| loading | Route data fetch | 🧪 backstop | `<Spinner/>` + "Loading…" renders while any page's query is in flight — needs a held-out test asserting the spinner is present during a delayed/pending fetch |
| error | Route data fetch | 🧪 backstop | `<ErrorState/>` with `Retry` renders on fetch failure, and `Retry` re-triggers the request — needs a held-out test simulating a rejected fetch and asserting the retry affordance calls `refetch()` |
| populated | Route data fetch | ✅ covered | Deferred by design — this phase intentionally does not define per-page populated-state visuals; Phase 2 (UI-02..UI-06) owns page content design against the same JSON contract |
| partial | Route data fetch | 🧪 backstop | Each route owns its own error boundary, so one page's failed fetch (e.g. `fixtures.json` 404) leaves the nav shell and every other route fully functional — needs a held-out test that fails one route's fetch and asserts nav/sibling routes remain interactive |
| zero-one-many | Route data fetch | ✅ covered | Deferred by design — singular/plural list-length copy is per-page content (Phase 2+); the shell-level empty-state fallback above is the only zero-item behavior this phase defines |
| overflow | Placeholder page content | ✅ covered | Heading/body text lives in the same max-width (`68rem`) wrapped container as real content will later use — no fixed-height clipping |
| long-text | Placeholder page content | ✅ covered | Placeholder copy is short and fixed per the Copywriting Contract, not user-generated — no truncation/ellipsis logic needed this phase |
