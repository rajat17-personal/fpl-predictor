<objective>
Create `data/backfill_snapshot.py`, a one-off-but-repeatable tool that reconstructs missing daily FPL bootstrap snapshots from Wayback Machine captures of `bootstrap-static`, then run it to close the nine-day hole (2026-09-01..06, 2026-09-08..10) in `data/snapshots/`.

Purpose: the price model (`models/price.py`) learns from day-over-day deltas that the FPL API never serves historically. WSL cron silently skipped nine days. The Wayback Machine holds ≥1 status-200 capture of the endpoint on every one of those days, so the training data is recoverable — but only until those captures are the last copy anyone has.

Output: a new module runnable as `python -m data.backfill_snapshot`, a network-free unit test for its date logic, and nine new schema-identical parquet files taking the archive from 5/14 to 14/14 days.
</objective>

Constants: `_CDX = "https://web.archive.org/cdx/search/cdx"`, `_WAYBACK = "https://web.archive.org/web/{ts}id_/https://fantasy.premierleague.com/api/bootstrap-static/"`, `_TARGET_URL = "fantasy.premierleague.com/api/bootstrap-static*"`, `_HEADERS = {"User-Agent": "fpl-ml-project/0.1"}`, `_TIMEOUT = 60`, `_TARGET_MIN = 150` (02:30 UTC, matching the daily cron's capture minute), `_JOB = "backfill"`.

`_get(url, params=None, *, retries=5, backoff=10.0)`: one shared archive.org GET honouring rate limits. On HTTP 429 or 5xx, sleep then retry — prefer the `Retry-After` response header when present and parseable as a number of seconds, else `backoff * 2 ** (attempt - 1) + random.random()`. Print each retry with the `[backfill]` tag and the attempt counter, matching `data/snapshot.py:131`'s retry-print style. A non-retryable 4xx raises immediately. Exhausting retries raises the last exception so the caller's exit code is non-zero.

`cdx_captures(day: dt.date) -> list[str]`: GET `_CDX` with `url=_TARGET_URL`, `from`/`to` both `day.strftime("%Y%m%d")`, `output=text`, `fl=timestamp,original,statuscode`, `filter=statuscode:200`. Split the response body on lines, split each line on whitespace, keep the first field when it is 14 digits. Return them sorted. An empty result is not an error here — it is a caller-visible "no capture available" signal.

`pick_capture(timestamps: list[str], target_min: int = _TARGET_MIN) -> list[str]`: pure, no I/O, no network. Parse each timestamp's `hh`/`mm` into minutes-past-midnight, sort ascending by `(abs(minutes - target_min), timestamp)`, return the full ordered list of candidates (best first). Returning the ordered list, not one value, is deliberate: `backfill_day` falls through to the next-best capture when the best one does not parse as bootstrap JSON.

`fetch_capture(timestamp: str) -> dict`: `_get(_WAYBACK.format(ts=timestamp))`, then `resp.json()`. Wayback occasionally serves an HTML error or a truncated body under the `id_` URL, so validate the shape before returning: require `elements` and `events` to be present and non-empty, otherwise raise `ValueError` naming the timestamp. `snapshot_frame` reads `boot["events"]` unguarded via `_next_gw`, so this check is what keeps a bad capture from writing a corrupt file.

`_ts_to_datetime(timestamp: str) -> dt.datetime`: `dt.datetime.strptime(timestamp, "%Y%m%d%H%M%S").replace(tzinfo=dt.timezone.utc)`. This datetime becomes `snapshot_frame`'s `ts`, so the written row's `date` is the archived day and `ts_utc` is the real capture instant — which is itself the provenance marker (a backfilled file's `ts_utc` is the archive's capture time, not the cron's ~02:30 run time).

`backfill_day(day: dt.date, *, max_candidates: int = 3) -> bool`: return `False` immediately when `SNAP_DIR/{day}.parquet` exists (idempotent per day, printed as a skip — no `--force` in v1). Otherwise list captures, order them with `pick_capture`, and try up to `max_candidates` in order; on a `ValueError` or JSON decode failure from one candidate, print the reason and move to the next. On success build `df = snapshot_frame(boot, _ts_to_datetime(timestamp))` and write atomically exactly as `take_snapshot` does: `tmp = out.with_suffix(out.suffix + f".{os.getpid()}.tmp")`, write, `os.replace(tmp, out)`, unlink the tmp inside an `except` before re-raising. Write with pyarrow so provenance rides in the file's key-value metadata without adding a column: build `pa.Table.from_pandas(df, preserve_index=False)`, take `table.schema.metadata or {}`, add keys `b"fpl_snapshot_source" -> b"wayback"` and `b"fpl_wayback_timestamp" -> timestamp.encode()`, `table = table.replace_schema_metadata(meta)`, then `pq.write_table(table, tmp)`. Downstream consumers read columns, never metadata, so this stays invisible to them — which is the point. Print the success line in `data/snapshot.py`'s format: filename, row count, next GW, plus the capture timestamp used. Return `True`.

CLI for this task: `argparse` with `--days` taking a comma-separated list of ISO dates, `--sleep` (float, default 6.0) applied between days, and `--max-candidates` (int, default 3). Parse `--days` through a small helper `parse_days(spec: str) -> list[dt.date]` that splits on commas, strips whitespace, and `dt.date.fromisoformat`s each — invalid input raises `SystemExit` with a message naming the bad token, following this repo's user-facing-CLI-error convention. `main` iterates days in order, calls `backfill_day`, sleeps `--sleep` seconds between days that actually hit the network, and returns 0 when every requested day ends up present on disk, 1 otherwise. Leave gap discovery and `--dry-run` to Task 2 — this task's `--days` path is the tracer.
