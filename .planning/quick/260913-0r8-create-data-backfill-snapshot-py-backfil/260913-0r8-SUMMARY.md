# Quick Task 260913-0r8 Summary

Built `data/backfill_snapshot.py`, a Wayback-Machine-backed tool that reconstructs missing daily FPL bootstrap snapshots by reusing `data/snapshot.py`'s own `snapshot_frame()` normalization, then ran it to close all nine missing days in `data/snapshots/` — the archive is now complete at 14/14 days (2026-08-31 through 2026-09-13).

## Accomplishments

- `data/backfill_snapshot.py`: `cdx_captures()` queries the Wayback CDX index for status-200 captures of `bootstrap-static` on a given UTC day; `pick_capture()` orders candidates by closeness to 02:30 UTC (matching the daily cron's capture minute); `fetch_capture()` retrieves and validates the raw `id_` JSON; `backfill_day()` writes an atomic, schema-identical parquet via the imported `snapshot_frame`/`SNAP_DIR`, embedding provenance (`fpl_snapshot_source=wayback`, `fpl_wayback_timestamp=<ts>`) in parquet key-value metadata rather than as a new column.
- `missing_days()`/`discover_missing()`: pure gap-detection logic over the days already on disk; `--dry-run` prints the resolved list and exits 0 with zero network calls.
- `tests/test_backfill_snapshot.py`: 8 offline tests covering `missing_days` (real archive shape, contiguous run, empty archive, never-includes-today), `pick_capture` (closeness ordering, tie-break-by-earlier), and `parse_days` (round-trip, malformed-token rejection). All pass with the network unavailable.
- Ran the tool against real archive.org data: filled `2026-09-10` as the tracer (Task 1), then the remaining eight days (`2026-09-01..06, 09-08, 09-09`) via gap discovery (Task 3). Zero 429s encountered across all 10 network-bound days at the plan's default `--sleep 6.0`; every day resolved on its first-choice candidate capture (no fall-through to a second/third candidate was needed).
- `data/snapshot.py`, `scripts/daily.sh`, `scripts/weekly.sh`, and `web/data/` are byte-identical to before this task (verified via `git diff --quiet`).
